MedicalAppointments_v2 - Microservicio de Citas y Pacientes
Persistencia Generica Independiente, Paginacion, Filtro Dinamico y Ordenamiento Dinamico
================================================================

Proyecto: MedicalAppointments_v2
Repositorio: rodolfo9611/MedicalAppointments_v2
Fecha: 23 de septiembre de 2026
Objetivo de la practica:
Crear una biblioteca de clases independiente enfocada en persistencia generica
(Nuget.Persistence), desacoplada de los microservicios, y reutilizarla en
diferentes microservicios (Citas y Pacientes) como un unico punto de acceso a
datos. La biblioteca incluye paginacion generica (GetPagedAsync), filtrado
dinamico con expresiones lambda en tiempo de ejecucion (System.Linq.Dynamic.Core),
consulta GetOneBy con filtrado generico y guardado por rango (List) de objetos.

----------------------------------------------------------------
1. REQUERIMIENTO DEL DOCENTE
----------------------------------------------------------------
El docente pidio construir una biblioteca de clases (Class Library) independiente
con metodos genericos, que se herede/reutilice entre diferentes microservicios,
evitando repetir la misma logica de persistencia en cada uno. La mayoria lo habia
creado dentro de un unico microservicio, que es lo que se corregio en esta
practica. La biblioteca tambien debe poder empaquetarse como NuGet para su
distribucion y reutilizacion.

----------------------------------------------------------------
2. NUEVA BIBLIOTECA DE CLASES: Nuget.Persistence
----------------------------------------------------------------
Se creo el proyecto de biblioteca de clases .NET 9 en nuggets/Nuget.Persistence:
- nuggets/Nuget.Persistence/Nuget.Persistence.csproj
- Paquetes NuGet:
  * Microsoft.EntityFrameworkCore (9.0.0)
  * Microsoft.EntityFrameworkCore.Relational (9.0.0) - Requerido para AsSplitQuery
  * System.Linq.Dynamic.Core (1.7.4) - Requerido para DynamicExpressionParser
- Configurado como empaquetable (PackageId=Nuget.Persistence, Version=1.0.0,
  IsPackable=true) para poder generar el .nupkg con dotnet pack.

Estructura interna:
A) Abstractions:
   - IRepository<TEntity, TKey>: Contrato generico CRUD (GetAllAsync,
     GetByIdAsync, AddAsync, UpdateAsync, DeleteAsync) enriquecido con:
     * GetPagedAsync (paginacion generica)
     * GetOneByAsync (consulta por filtro generico)
     * AddRangeAsync (guardado por rango)
   - PagedResult<TEntity>: Contenedor del resultado paginado (Data, TotalRecords,
     PageSize, CurrentPage, TotalPage).

B) Implementations:
   - Repository<TEntity, TKey>: Implementacion sobre DbContext y DbSet<TEntity>.
     * Obtencion dinamica de la clave primaria mediante metadata de EF Core.
     * GetPagedAsync: aplica includes, evalua el filtro Where, aplica
       AsSplitQuery si se solicita, calcula TotalRecords con CountAsync,
       aplica el ordenamiento (OrderBy dinamico por campo o lambda) y ejecuta
       Skip/Take para materializar la pagina.
     * GetOneByAsync: aplica includes mas filtro y retorna FirstOrDefaultAsync.
     * AddRangeAsync: usa DbSet.AddRangeAsync y un unico SaveChangesAsync.

C) Common:
   - Filter: Clase estatica con FromStringExpression<TModel>(query), que usa
     DynamicExpressionParser.ParseLambda para interpretar condiciones en
     cadenas (ej: "EstadoCitaID == 1" o "Motivo.Contains(\"Consulta\")").
   - PagedDto<TEntity>: Objeto generico de transferencia para respuestas
     paginadas.
   - HttpResponse<T>: Envoltorio estandar para respuestas HTTP (Success,
     Message, Data).
   - RequestParametersGets: Clase base con PageNumber, PageSize, Filter y
     OrderBy.

----------------------------------------------------------------
3. ESPECIFICACIONES IMPLEMENTADAS
----------------------------------------------------------------
1) GetOneBy con filtrado generico (similar a la paginacion):
   - Firma: GetOneByAsync(Expression<Func<TEntity,bool>> filter,
     asNoTracking, cancellationToken, params includes).
   - El handler/controlador convierte la cadena de filtro con
     Filter.FromStringExpression<TEntity> y retorna el primer resultado.
   - Endpoints: GET api/Citas/one?filter=... y GET api/Pacientes/one?filter=...

2) Paginacion generica con OrderBy dinamico por cualquier campo:
   - GetPagedAsync acepta el parametro dinamico orderBy (string) que ordena
     por cualquier propiedad, con direccion opcional (asc/desc), mediante
     System.Linq.Dynamic.Core. Se conserva la variante por lambda
     (orderByExpression) como alternativa tipada.
   - RequestParametersGets incluye la propiedad OrderBy.
   - Endpoints: GET api/Citas/paged?orderBy=FechaHoraInicio desc y
     GET api/Pacientes/paged?orderBy=Nombre desc.

3) Guardado por rango de valores (List):
   - Firma: AddRangeAsync(IEnumerable<TEntity> entities, cancellationToken).
   - Persiste una lista de objetos en una sola operacion SaveChangesAsync.
   - Endpoints: POST api/Citas/range y POST api/Pacientes/range con List
     de entidades.

----------------------------------------------------------------
4. INTEGRACION EN LOS MICROSERVICIOS
----------------------------------------------------------------
La misma biblioteca se agrego por ProjectReference desde nuggets/ a DOS
microservicios (configuracion de BD distinta, acceso a datos unico):

A) Microservicio de Citas (MedicalAppointments.sln):
   - MedicalAppointments.Domain: ICitaRepository : IRepository<Cita,long> e
     IEstadoCitaRepository : IRepository<EstadoCita,int>. Se elimino la
     IGenericRepository interna.
   - MedicalAppointments.Persistence: CitaRepository y EstadoCitaRepository
     heredan de Repository<...>. Se elimino la GenericRepository interna.
   - MedicalAppointments.Core (CQRS con MediatR):
     * GetCitaDto.
     * GetCitasPagedQuery (+Handler): usa Filter y OrderBy dinamico.
     * GetCitaOneByQuery (+Handler): usa GetOneByAsync con filtro generico.
     * CreateCitasCommand (+Handler): usa AddRangeAsync.
   - MedicalAppointments.Api: endpoints paged, one y range con documentacion
     XML para Swagger. Configuracion de BD: SQL Server (connection string
     CitasDB).

B) Microservicio de Pacientes (MicroservicioPacientes.sln):
   - MicroservicioPacientes.Application: IPacienteRepository : IRepository<Paciente,int>.
   - MicroservicioPacientes.Infrastructure: PacienteRepository hereda de
     Repository<Paciente,int> (solo constructor).
   - MicroservicioPacientes.Api: PacientesController usa los metodos
     genericos y expone paged, one y range. Configuracion de BD: InMemory
     (PacientesDb).

----------------------------------------------------------------
5. MANEJO DE ERRORES
----------------------------------------------------------------
- Filtro u OrderBy invalido: Filter.FromStringExpression y el OrderBy dinamico
  lanzan ValidationException; los handlers/controladores la capturan y
  responden HTTP 400 BadRequest con HttpResponse (Success=false, Message).
- Parametros de paginacion invalidos (pageNumber/pageSize < 1): HTTP 400.
